# РБПО, лабораторная работа №3

REST API для проката туристического снаряжения. Проект продолжает предметную область ЛР №2, но хранит данные в PostgreSQL через Spring Data JPA.

## Что реализовано

- PostgreSQL, Spring Data JPA и Hibernate;
- пять связанных сущностей: пользователь, единица снаряжения, заказ, позиция заказа и акт осмотра;
- CRUD для каждой сущности;
- внешние ключи, `NOT NULL`, уникальные инвентарные номера и email, ограничение уникальности единицы снаряжения в одном заказе;
- серверное время для заказа и акта осмотра;
- ограниченный пользователь PostgreSQL `rental_app`;
- тестовые записи, создаваемые при первом запуске пустой БД;
- Postman-коллекция с CRUD и сценарием бизнес-операций.

## Предметная модель

```text
AppUser 1 --- * RentalOrder 1 --- * RentalItem * --- 1 EquipmentUnit
                                      |
                                      *
                                      |
                               InspectionRecord
```

- `AppUser`: клиент проката.
- `EquipmentUnit`: конкретная единица снаряжения с инвентарным номером, ценой и состоянием.
- `RentalOrder`: период аренды, клиент, статус и итоговая стоимость.
- `RentalItem`: единица снаряжения в заказе с зафиксированной суточной ценой и статусом возврата.
- `InspectionRecord`: акт выдачи или возврата позиции аренды.

## Бизнес-операции

1. `POST /api/rental-orders/{id}/items`: добавить доступную единицу в черновик заказа. Единица резервируется и становится `RENTED`.
2. `POST /api/rental-orders/{id}/issue`: выдать заказ. Операция допустима только для непустого `DRAFT`; создаёт акты выдачи по всем позициям.
3. `POST /api/rental-items/{id}/return`: вернуть позицию. Создаёт акт возврата, меняет состояние снаряжения на `AVAILABLE` или `MAINTENANCE`, завершает заказ после возврата всех позиций.
4. `POST /api/rental-orders/{id}/cancel`: отменить черновик и освободить все зарезервированные единицы.
5. `POST /api/equipment-units/{id}/maintenance`: отправить доступную и не участвующую в активной аренде единицу в обслуживание.

Все операции выполняются в сервисном слое в транзакциях. Некорректное состояние возвращает `400`, отсутствующая сущность - `404`.

## Настройка PostgreSQL

1. Создай БД `tourism_rental` от имени администратора PostgreSQL.
2. Выполни [`db/create-app-user.sql`](db/create-app-user.sql), заменив пример пароля на свой.
3. Скопируй `.env.example` в `.env` и укажи параметры подключения. `.env` добавлен в `.gitignore`.
4. Перед запуском задай переменные среды из `.env` любым удобным способом.

Пример для PowerShell:

```powershell
$env:SPRING_DATASOURCE_URL = "jdbc:postgresql://localhost:5432/tourism_rental"
$env:DB_USER = "rental_app"
$env:DB_PASSWORD = "ваш-пароль"
mvn spring-boot:run
```

После первого запуска Hibernate создаст таблицы, а приложение добавит несколько демонстрационных записей.

## Запуск и проверка

```bash
mvn clean verify
mvn spring-boot:run
```

Сервис запускается на `http://localhost:8080`.

Postman-коллекция находится в [`postman/RBPO-Lab3.postman_collection.json`](postman/RBPO-Lab3.postman_collection.json). Она использует переменную `baseUrl` со значением `http://localhost:8080` и сохраняет созданные идентификаторы в переменные коллекции.

## Статусы HTTP

- `200 OK`: чтение, изменение и бизнес-операции;
- `201 Created`: создание сущности и добавление позиции в черновик;
- `204 No Content`: удаление;
- `400 Bad Request`: нарушены правила предметной области;
- `404 Not Found`: сущность не найдена.
